# Scarab of RA implementation notes

Playable native browser reconstruction based on the extracted Help and Hint resources of Macintosh Scarab of RA 1.4. Modern presentation is the default, with an optional original interface, German translation and subtle material colours.

## Run and verify

Run commands from the repository root. Requires Node.js 22 or newer. Install dependencies with `npm ci`; no frontend build step is needed.

```sh
npm ci
npm run dev
npm test
```

Open http://127.0.0.1:4173. The Node server serves `dist/` and the shared PostgreSQL leaderboard API. See [deployment instructions](../DEPLOYMENT.md) for the database, production startup and Coolify setup.

## Original material

The 512 × 342 screen preserves the original major window coordinates. Movement controls use PICT 128–133 and 150–152. All 81 PICT resources have been decoded into PNGs; the renderer uses original item, door and darkness graphics. The original Help and Hint texts are included verbatim. The trap sound is decoded from snd 8192. Resource extraction scripts and original evidence are in the repository root under `tools/` and `reference/`.

ChicagoGrid is a 12-pixel rasterization of ChicagoFLF, a public-domain Chicago approximation by Robin Casady. It substitutes for the original system font. Source: https://fontlibrary.org/en/font/chicagoflf . The original game artwork and text remain copyright Rick Holzgrafe / Semicolon Software. This reconstruction does not grant a new license to the original assets.

## Playable scope

Exploration from 3×3 to 20×20, original depth-dependent weighted stocking, mapping and orientation, wall inscriptions, inventory quantities and reordering, throwing and breakage, food/oil/weight, keys, all four traps, planks, first aid, poison and antidote, poles, nets, whips, darts and dart guns, nightglasses, melons, deposits, three relics and the ending score.

Lionesses, monkeys and cobras can sleep, wander, follow or flee the player, attack and be captured. Monkeys carry stolen objects and release them when incapacitated. Guardians track the player. Carrying the Scarab reduces their otherwise lethal attack to 30 damage; throwing the Scarab destroys one for 500 prestige. A new level can awaken another Guardian.

Arrows or WASD move and turn; Q/E/R peek; X turns around; Space waits; G picks up; U uses; T throws; I inspects; M opens the map. Inventory double-click uses the object. Menus expose quantities and throwing distance. Drag inventory objects to rearrange them. Scores are stored in a shared PostgreSQL database through the server API. Saved games preserve enemy and poison events; v2 saves migrate without rerolling their current level.

## Fidelity and verification

Rules are transcribed from the supplied 1.4 executable's CODE and DATA resources, with offsets recorded in `docs/originalvergleich.md`. `item-types.js` is generated by `tools/export_item_types.py`. This is a reconstruction, not emulation: QuickDraw's random sequence is not reproduced. Dialogs other than the map and nightglasses palette, substitute font, wall-text perspective, and same-tick event ordering still have fidelity limits. MacEmu was used for visual reference, but no complete frame-by-frame differential playthrough has been achieved. Do not describe this as perfectly equivalent.

The original hints mention feeding animals; the extracted food type has no throw callback and the examined generic throw handler does not implement feeding. Food therefore follows that generic handler. This discrepancy remains documented for a controlled original-runtime experiment.

Automated tests cover maze connectivity/growth, resource clocks, stocking gates and counts, load limits, traps, poison, creature behavior, Guardian interactions, throwing, tool interruption, quantities, scoring, saves and rendering. Development-only `/__scenario?case=tools` and `/__scenario?case=guardian` provide repeatable browser QA; they are unavailable when the production server is running. `/__render-check` shows plank and gold perspective.

## Architecture

`engine.js` is independent of rendering. `render.js` draws the original artwork in a reconstructed perspective. `app.js` provides input, original menus, map and browser storage. Simulation advances only on actions; graphics and peek do not consume random state or game time.


Junction contours now follow CODE 2:307c–3a7a, including side-neighbour walls and narrow returns. Regression scenes cover left/right/both openings and depth under haze. News/inventory scroll arrows are clickable and repeat while held. Map layout uses integer zoom and integer cell boundaries.

Map walls use the original 2×2 pen on a shared bitmap, with uniform floor(294/n) cell sizes. Seven mapping tests cover seamless walls, fill patterns and the speed-dependent mapped/unwalked → walked transitions.

## Original / Modern UI foundation

Press **O** (either case) or use the **UI: Original / Modern** footer button. The preference persists in `scarab-ra-ui-mode-v1`, separately from expedition saves. Modern is the default; an explicitly chosen Original preference is retained. Switching changes presentation only: no game action, elapsed tick, RNG call, reload or reconstruction of the game. Dialogs, note drafts and selection remain intact. Typing in editable controls, IME composition and browser shortcuts never toggle modes.

- `dist/ui-mode.js`: isolated preference controller, shortcut guard and mode API. No dependency on the engine or saved game.
- `html[data-ui-mode="original"|"modern"]`: shared mode scope, including dialogs and menus outside the game frame.
- `dist/style.css`: preserved baseline/original UI.
- `dist/modern.css`: modern-only overrides and design tokens. Scope every modern rule under `html[data-ui-mode="modern"]`; do not change baseline styles for a modern-only improvement.
- `app.js`: one live game and shared action handlers. Future modern controls must call these existing actions rather than duplicate game logic. Keep DOM IDs unique and preserve dialog/input state when updating presentation.

Modern now uses a viewport-filling corridor, a bottom inventory dock, a status strip, a persistent minimap and optional news. Original remains the comparison mode. Three dedicated tests cover switching, independent persistence, unavailable storage and shortcut exclusions.


## Modern HUD — first playable proposal

`modern.css` scopes the new responsive layout; `modern-hud.js` reads the shared game state without advancing it. The native 304×218 corridor framebuffer is scaled proportionally to cover the space above the dock (outer edges may crop according to aspect ratio). Original sprites, wall contours and monochrome style are retained.

Inventory slots show extracted item icons, quantities and selection. Use / Get Info / Drop / Throw call the same handlers as Original; double-click and drag-reordering remain available. The dock scrolls horizontally for larger inventories, with previous/next controls. The minimap shows only mapped cells, uses readable grayscale fills at reduced size, tracks facing and opens the full map. When orientation is lost the position arrow disappears. Facing display is an explicit modern HUD addition, available without owning a compass.

News can be hidden using a persisted browser preference; messages continue to be recorded. Fullscreen is opt-in through a button and uses the native Fullscreen API; supported browsers provide Esc to exit. If unavailable, an inline explanation is shown and the game remains window-filling. Both modes share the same expedition and can be changed with O, including while a dialog is open.

Browser QA: item selection/use and removal, pickup quantities, news toggle, fullscreen enter/exit UI, map open/close, Original/Modern switch with selection preserved, 1440×900 and 390×844 layouts. Two tests check the minimap direction/position and that unknown walls are not revealed. The large map and other dialogs retain their existing design for this first proposal.

## Current expedition

The current expedition is checkpointed automatically in this browser. Continue
expedition restores it after a reload; New expedition starts over after confirmation.
Explicit saved games remain a separate slot. Revision checks and browser Web Locks
prevent older tabs from overwriting a newer checkpoint. A conflicting tab asks for
a reload. Completed expeditions leave a tombstone so an older tab cannot revive them.
